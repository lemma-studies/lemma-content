# Lemma Content — AI Maintenance Playbook

This is `lemma-studies/lemma-content`, the public canonical repo for lemma theological studies.

## What this repo is

Public canonical content, Astro Starlight site, publishing pipeline, AI-first surfaces. Companion to private `lemma-studies/lemma-workroom` (work product, dispositions, restricted primary sources, chore logs, benchmark canaries).

## Where things live

- **Chapters (canonical):** `studies/<slug>/*.md` — edit these; never edit compiled output
- **Compiled per-version:** `studies/<slug>/versions/vN.N/` — regenerated by compile; committed for frozen URLs
- **Study schema:** `studies/<slug>/study.yaml` — DOIs, versions, tags
- **Claims registry (per study):** `studies/<slug>/claims.jsonl`
- **Primary-source refs (per study):** `studies/<slug>/primary-sources.json` — points into `primary-sources/manifest.json`
- **Central primary sources:** `primary-sources/manifest.json` + `primary-sources/{PD,CC}/`

- **Site chrome:** `site/src/`, `site/public/`, `site/astro.config.mjs`
- **Tooling:** `scripts/{compile-study,verify,review,lemma-cli}/`
- **Data (public, transparency-safe):** `data/phase-state.yaml` (SINGLE source of truth for phase), `data/failure-modes.yaml`, `data/health-checks.yaml`, `data/last-heartbeat.txt`, `data/last-health-check.json`
- **Design + specs:** `docs/superpowers/specs/` — canonical design at `2026-08-11-lemma-content-architecture-design.md`
- **Plans:** `docs/superpowers/plans/` — execution plans per phase

## Chapter files are canonical (fold discipline)

Chapters are the single source of truth. All derivatives regenerate from them:

- Compiled composite `<slug>-vN.N.md` — Release only (not committed)
- Compiled per-chapter `versions/vN.N/*.md` — committed for stable frozen URLs
- Breadcrumbed `<slug>-vN.N.rag.md` — Release only
- PDF — Release + committed to `versions/vN.N/`
- `xrefs.json` — extracted per compile, committed

**When applying external-reviewer findings:** fold into the chapter file, never into the compiled `.md`. Then re-run `npm run compile:study --study <slug> --version v<N+1>` to rebuild derivatives from chapters. See historical case notes below.

## Recurring chores

Workroom `chore-log.jsonl` is the queryable source of truth (drift detection via `jq -s 'group_by(.chore) | map(max_by(.run_at))'`). Retention chores quarterly per workroom `retention-schedule.md`.

## Failure recovery

`data/failure-modes.yaml` — every mode has `autonomy: auto | propose | human-gate`.

- `auto` — AI can execute unattended within `max_auto_attempts`/`auto_cooldown_hours`. Circuit-breaker downgrades to `propose` on repeated failure.
- `propose` — AI diagnoses + opens PR/Issue; human approves and executes.
- `human-gate` — AI never touches unattended. All erasure work is human-gate.

**NEVER** silently edit `CLAUDE.md`, `data/failure-modes.yaml`, or `data/phase-state.yaml` — every change goes through commit with rationale.

## Verification patterns

- Session start (if `data/last-health-check.json` timestamp > 14 days): `npm run health-check -- --local`
- After any release: `npm run verify-release -- --tag <slug>/vN.N`
- To simulate GDPR erasure: `npm run dry-run-erasure -- --subject <id>` (never auto-executes)
- Sanity-check the lemma-cli scaffold itself: `npm run self-test`

## Anti-patterns

- **Never** silently edit `CLAUDE.md`, `data/failure-modes.yaml`, or `data/phase-state.yaml`
- **Never** tag a version — Tim executes `git tag && git push origin <tag>` (tag = human gate for irreversible Zenodo publish per design §6.2)
- **Never** edit compiled files in `studies/<slug>/versions/*/*.md` — regenerated per compile; edits are silently lost
- **Never** put `[skip ci]` or CF-skip phrases in Job 2d commits (suppresses CF Pages PDF deploy)
- **Never** create test/synthetic study slugs on `main` (blocks release via `no_test_slugs_on_main` check)
- **Never** commit raw email PII to `main` — belongs in workroom `feedback-inbox/`
- **Never** publish reader canary phrases to public benchmarks — they live in workroom `absorption-benchmarks/`
- **Never** make `gig8/lemma-legacy` public — history contains workroom material

## Session start ritual

1. Read this file.
2. Check `data/last-health-check.json` timestamp; if > 14 days: `npm run health-check -- --local`.
3. `gh issue list --label verify-release-failure` — triage any open failures before starting new work.
4. If touching failure-modes.yaml or health-checks.yaml: run `npm run self-test` before committing.
5. Proceed with task.

## Historical fold-discipline lesson (2026-08)

The "What Is the Perfect" v4.2→v4.9 arc (Aug 2026) ran ~7 rounds of external-reviewer fold work applied directly to the compiled `.md` file. Chapters stayed stale for a week; `lemma.gig8.com` served pre-fold text while reviewers were sent the compiled version. This is why the "edit chapters, then recompile" discipline is in the Global Constraints of every phase plan and why the `review:dispatch` script runs a drift check that refuses to send a package whose manuscript body doesn't match the current chapters.
